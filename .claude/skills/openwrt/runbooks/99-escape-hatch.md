# Runbook 99 — Escape hatch: прямой SSH через `raw-ssh.sh`

## Принцип

Этот навык управляет роутером **только** через `bin/*` скрипты. `raw-ssh.sh` — это аварийный люк, **не** «удобный способ выполнить команду по-быстрому». Каждый его вызов логируется в `journal.md` с тегом `raw_ssh_session` и требует **явного** согласия пользователя в чате.

## Когда уместно использовать

1. **Доктор показывает странное**, что не покрыто скриптами:
   - неизвестная UCI-секция в `/etc/config/network`, не описанная в шаблонах;
   - кастомный init.d скрипт, который ставил кто-то до нас;
   - подозрение, что zapret имеет нестандартную strategy (`nfqws -qnum=42 ...`), которую не видит probe;
   - artifact'ы предыдущего setup'а, конфликтующие с нашими (другие sing-box-config, awg-tunnel и т.п.).
2. **Разовая диагностика**, для которой **нет** специализированного скрипта:
   - тестовый `ping`/`mtr`/`traceroute` с роутера к VPN-серверу;
   - чтение `dmesg`, `logread -f` в реальном времени;
   - просмотр `iptables-save`/`nft list ruleset` целиком (если `health.sh` показывает только summary).
3. **Пользователь явно просит**: «дай мне SSH», «открой shell на роутере», «хочу сам зайти». Тогда это его осознанное желание; всё равно проводи через `raw-ssh.sh`, чтобы получить логирование в journal.

## Когда НЕ оправдано

- **«Лень делать через add-domain»** → нет, используй `bin/add-domain.sh`. То же для add-vpn, add-proxy, remove-*, restore, backup.
- **Любая mutating операция, для которой есть скрипт** → НЕТ. Скрипты делают snapshot + atomic write + validate + auto-rollback. Сырой SSH этого не делает.
- **«Просто посмотреть статус sing-box»** → `bin/health.sh --router <alias>`.
- **«Посмотреть последние логи watchdog»** → `bin/logs.sh --router <alias> --source watchdog --lines 50`.
- **«Сделать backup»** → `bin/backup-now.sh --router <alias> --label "<reason>"`.
- **«Перечитать конфиг sing-box»** → `add-domain.sh` сделает это сам; для разового reload нужен скрипт-фича-запрос post-V1.

Если можешь ответить через `health.sh`/`doctor.sh`/`logs.sh`/`snapshot-list.sh` — **используй их**. Сырой SSH — последний резерв.

## Процедура

### Шаг 1. Сформулируй причину и попроси явное подтверждение

В чате, перед запуском `raw-ssh.sh`, скажи **дословно** (адаптируй под язык):

```
Нужно открыть прямой SSH к <alias>, потому что <короткая причина>.
Что я планирую посмотреть/сделать:
- ...
- ...

⚠ Через сырой SSH:
- НЕ создаётся автоматический snapshot.
- Если что-то изменишь руками — auto-rollback'а не будет.
- В memory/<alias>/journal.md попадёт ТОЛЬКО факт сессии (reason, duration_s, exit_code) — команды НЕ логируются, скрипту они недоступны.

Подтверди "yes/ok/да" — без явного согласия я не запускаю.
```

Без ответа «yes», «ok», «да», «давай», «жми» (или явного эквивалента) — **НЕ запускай**. Если пользователь сказал «погоди», «не надо», «отмена» — закрой ветку.

### Шаг 2. Запустить

```bash
bin/raw-ssh.sh --router <alias> --reason "<короткое описание>"
```

`--reason` — обязательно (1-2 строки, без секретов). Это пойдёт в `journal.md`. По контракту SKILL.md, `raw-ssh.sh` открывает интерактивную SSH-сессию (через тот же `ssh_alias` из `~/.ssh/config`).

Exit codes (стандартные для bin/*):
- `0` — сессия закрыта нормально (пользователь сделал `exit`).
- `2` — SSH упал / роутер не в реестре.
- `13` — `--reason` пустой или содержит секреты.
- `64` — bad CLI args.

### Шаг 3. После закрытия сессии — ОБЯЗАТЕЛЬНО re-sync

```bash
bin/doctor.sh --router <alias>
```

Это важно, потому что:
- Пользователь мог что-то изменить руками (даже если «только посмотреть» — мог случайно вызвать reload какого-то сервиса).
- `state.md` нужно перерендерить, иначе он покажет устаревшие галочки.

### Шаг 4. Если пользователь делал mutating операции — записать в quirks.md

Спроси пользователя: «Что именно ты делал в сессии? Опиши коротко — я запишу в `quirks.md`, чтобы в следующий раз скрипт мог это учесть/воспроизвести».

Не угадывай, не делай предположений по `logread`. Жди от пользователя описания.

Если пользователь говорит «ничего не менял, только смотрел» — ок, ничего в quirks не пишем, но `journal.md` уже зарегистрировал raw_ssh_session.

Если пользователь описал mutating действие — добавь запись в `memory/<alias>/quirks.md` (это **единственный** memory-файл, который агент имеет право редактировать руками за пределами скриптов, и только append-новой секцией). Формат — см. шаблон в `memory/_templates/quirks.md` (`### <тег>` + тело).

**Дополнительно напомни пользователю** (явно, в чате):
> Я записал твои действия в quirks.md. Имей в виду: ты делал mutating-операции через сырой SSH, поэтому **snapshot не создавался** и **auto-rollback'а нет**. Если хочешь страховку — могу прямо сейчас сделать `bin/backup-now.sh --router <alias> --label "post-raw-ssh-<reason>"`, чтобы зафиксировать новое состояние как точку отката.

## Что обновляется в memory/

- `memory/<alias>/journal.md` — два события:
  - `raw_ssh_session_opened` — `reason`, `mutations_allowed`, `ssh_target` (записывается ДО открытия сессии).
  - `raw_ssh_session_closed` / `_aborted` — `reason`, `mutations_allowed`, `duration_s`, `exit_code`, `ssh_target`.
  - Команды, набранные пользователем В сессии — НЕ логируются (скрипту они недоступны).
  - Привязка к `quirks.md` — через ручную запись агента, не автоматически.
- `memory/<alias>/quirks.md` — новая секция, **только** если пользователь описал mutating-действия.
- `memory/<alias>/state.md` — перерендерен после `doctor.sh`.
- **НЕ обновляется** автоматически: `domains.md`, `vpns.md`, `proxies.md`. Если пользователь руками добавил VPN через сырой SSH — `vpns.md` останется старым. Это известное ограничение V1.

## Что сказать пользователю (после сессии)

```
SSH-сессия закрыта (длительность ~<seconds>s).
- Журнал: memory/<alias>/journal.md (event raw_ssh_session, reason: "<reason>")
- doctor.sh перерендерил state.md
- quirks.md: [добавил секцию <тег> / без изменений]
- snapshot НЕ сделан автоматически (raw SSH этого не умеет)

[Если были mutating-операции:]
Если хочешь зафиксировать новое состояние как точку отката:
  bin/backup-now.sh --router <alias> --label "post-raw-ssh-<short-desc>"
```

## Edge cases

- **Пользователь сам ввёл секрет в чат во время описания причины** (например, `--reason "проверить vless://..."`) → откажись запускать, попроси переформулировать reason без секрета. Скрипт сам отвергнет exit 13, но лучше до этого.
- **Сессия упала по таймауту** → exit ≠ 0. Запусти doctor.sh всё равно, чтобы зафиксировать состояние.
- **Пользователь забыл `exit` и просто закрыл терминал** → `raw-ssh.sh` всё равно вернёт control, может с не-0 кодом. doctor.sh обязателен.
- **Несколько сессий подряд (debugging marathon)** → можно. Каждая записывается в journal как отдельный event. Не сваливай несколько `--reason` в один.

## НЕ ДЕЛАТЬ

- **НЕ запускать `raw-ssh.sh` без явного подтверждения** пользователя в текущем чате. «Подразумеваемое согласие» не подходит.
- **НЕ использовать `raw-ssh.sh` для операций, у которых есть скрипт.** Если поймал себя на мысли «сейчас зайду по SSH и поправлю один JSON» — стоп, ищи скрипт.
- **НЕ молчать про отсутствие snapshot'а** после mutating-сессии. Это главная разница с обычными `bin/*` скриптами.
- **НЕ редактировать `domains.md`/`vpns.md`/`proxies.md` руками** после raw-ssh сессии. Если они врут — это ограничение V1; обсуди с пользователем, не пытайся залатать.
- **НЕ пытаться передать пароль роутера через `--reason` или другие флаги.** Если SSH-ключ не работает — путь через `setup-ssh.sh`, не через raw-ssh.
