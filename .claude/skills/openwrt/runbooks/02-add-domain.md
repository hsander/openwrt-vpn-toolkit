# Runbook 02 — Добавить домен в VPN-список

## Когда использовать

Триггеры от пользователя: «добавь домен youtube.com», «пусть chatgpt.com идёт через VPN», «заверни <домен> в туннель», «не работает <сайт>, заверни».

Pre-conditions (что должно быть в `memory/<alias>/state.md`):
- Пункт 11 «`config.json` валиден» = ✅
- Пункт 12 «`rules/vpn-domains.json` есть» = ✅ (или будет создан скриптом из v3-болванки)
- Пункт 13 «tproxy запущен» = ✅
- Пункт 14 «≥1 VPN outbound + auto-failover» = ✅

Если что-то из этого `❌` → НЕ запускай `add-domain.sh`. Отправь пользователя на `runbooks/01-first-time.md` («VPN ещё не поднят на этом роутере; сначала первичная настройка»).

## Шаг 1. Что спросить у пользователя

1. **Домен.** Если пользователь написал просто «добавь youtube» — переспроси: «`youtube.com` или какой-то поддомен?». Не угадывай.
2. **Outbound (опционально).** По умолчанию — `auto-failover` (рекомендация для 95% случаев). Спрашивай только если пользователь сам упомянул конкретный tag («через node-de», «через ноду Германии»). Если упомянул — сверь tag со списком в `memory/<alias>/vpns.md`. Если такого tag'а нет — переспроси.

### Валидация домена локально (до запуска скрипта)
- Должен быть в нижнем регистре. Если пользователь написал `YouTube.COM` — приведи к `youtube.com` молча и подтверди в финальном сообщении.
- Только буквы, цифры, точки, дефис. Никаких `https://`, `www.` (точнее: `www.` — это валидный поддомен, но обычно лишний; уточни у пользователя).
- НЕ должен быть IP-адресом (если выглядит как `1.2.3.4` — скажи: «это IP, а скрипт принимает только домены; для IP есть отдельный скрипт `add-ip.sh`»).
- НЕ должен содержать `vless://`, `bot<digits>:`, `=` — это значит, что в команду случайно прилетел секрет. Откажись, попроси перевводить.

### Спец-случай: пользователь хочет «закрыть страну»
Триггеры: «заверни весь Гугл», «весь Россия через VPN», «гео-список такой-то».

Это **не одиночные домены**, а гео-списки. В текущей версии (V1) `add-domain.sh` принимает только отдельные домены, по одному. Скажи пользователю:

> В V1 я могу добавлять домены по одному. Для гео-листов (вся РФ, весь Google и т.п.) нужен отдельный скрипт, который пока не реализован. Хочешь — добавлю несколько ключевых доменов руками сейчас (`youtube.com`, `googlevideo.com`, …) и зарепортим feature request на geo-lists post-V1.

НЕ пытайся обойти через несколько вызовов в цикле без явного согласия пользователя.

## Шаг 2. Выполнение

```bash
bin/add-domain.sh --router <alias> --domain <domain>
```
(добавь `--outbound <tag>`, только если пользователь явно попросил конкретный outbound)

Что делает:
1. pre-backup на роутере → snapshot ID запоминается;
2. SCP `vpn-domains.json` локально, мердж в `domain_suffix` первого правила (или seed v3);
3. валидация локально + `sing-box rule-set format` на роутере + `sing-box check`;
4. atomic mv в `/etc/sing-box/rules/vpn-domains.json`;
5. hot-reload sing-box (без рестарта tproxy);
6. обновление `memory/<alias>/domains.md` + журнал.

Exit codes:
- `0` — добавлено. Если домен **уже был** — скрипт делает no-op idempotent skip, тоже exit 0. Распознай по stderr (там будет «уже в списке»).
- `2` — SSH упал ИЛИ `config.json` отсутствует. Если SSH — попроси проверить связь. Если конфиг — отправь на `01-first-time.md`.
- `13` — невалидный домен / секрет в аргументе. Покажи stderr пользователю.
- `20` — rollback сработал (например, sing-box check упал после мерджа). Snapshot восстановлен. Покажи stderr; это редкий случай — обычно означает, что rule-set был руками сломан до нашего вмешательства. Предложи `bin/doctor.sh --router <alias>` для перепроверки.
- `64` — bad CLI args.

## Шаг 3. Подтверждение

Прочитай `memory/<alias>/domains.md` — должна появиться новая строка таблицы вида `| <домен> | <outbound> | <ISO time> | claude-code |`.

Если строка не появилась, но exit был `0` — это баг скрипта, не молчи: скажи пользователю и предложи `bin/doctor.sh --router <alias>` для re-sync.

## Что обновляется в memory/

- `memory/<alias>/domains.md` — новая строка таблицы.
- `memory/<alias>/journal.md` — событие `add_domain` с `domain`, `outbound`, `snapshot_before`, `result`.
- `state.md` и `vpns.md` **не меняются** (новых outbound'ов нет).

## Что сказать пользователю

```
Добавил <домен> в VPN-роут через <outbound>.
- Файл на роутере: /etc/sing-box/rules/vpn-domains.json
- Snapshot до: <snap-id> (восстановить: «откати к <snap-id>»)
- Hot-reload: sing-box перечитал правила без рестарта

Проверь: открой <домен> с устройства в LAN, или curl через :4000.
```

Если был no-op skip (домен уже был): «`<домен>` уже в списке, никаких изменений не сделал.»

## Edge cases / частые ошибки

- **Пользователь добавляет уже добавленный домен** → no-op, exit 0, не паникуй. Просто сообщи.
- **Hot-reload не сработал, но exit 0** → скрипт обещает откат на `service reload`, но если оба пути сработали с warning'ом — он всё равно вернёт 0. Если пользователь говорит «домен всё ещё не идёт через VPN» — `bin/doctor.sh` + `bin/health.sh --router <alias>`.
- **Домен с wildcard (`*.example.com`)** → в rule-set v3 `domain_suffix` уже работает как «все поддомены», так что писать `example.com` достаточно. Если пользователь дал `*.example.com` — отрежь `*.` молча и подтверди в финальном сообщении.
- **Очень длинный список доменов от пользователя одним сообщением** → попроси разбить или подтвердить, что хочешь добавить их все по очереди (вызови `add-domain.sh` N раз последовательно, на каждом проверяя exit code; если хоть один не `0` — стоп, не продолжай).

## НЕ ДЕЛАТЬ

- НЕ редактировать `domains.md` руками — только через `add-domain.sh`/`remove-domain.sh`.
- НЕ запускать `add-domain.sh` если state.md показывает, что VPN не установлен (→ 01).
- НЕ обрабатывать гео-списки через цикл без явного согласия пользователя.
- НЕ молчать про exit 20 — это значит, что что-то системно сломано на роутере.
